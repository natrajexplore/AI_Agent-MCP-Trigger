MCP Integrated AI Agent Tools – n8n

Overview

This project demonstrates how to build an MCP (Model Context Protocol) integrated AI Agent in n8n.

The solution is implemented as two n8n workflows:

MCP Server – exposes multiple business and productivity tools through an MCP endpoint.

AI Agent MCP Enabled – receives a chat request, uses an OpenAI chat model and memory, and connects to the MCP Server to select and execute the appropriate tools.

This architecture allows an AI Agent to access external capabilities through a centralized MCP Server instead of connecting every tool directly to the agent.

Included Workflows

1. AI Agent MCP Enabled

Workflow file: AI Agent MCP Enabled (1).json

The AI Agent workflow contains:

When chat message received – starts the workflow from an incoming chat message.

AI Agent – interprets the user's request and decides when a tool is required.

OpenAI Chat Model – uses gpt-4.1-mini as the configured chat model.

Simple Memory – provides conversation memory to the AI Agent.

MCP Client – connects the agent to the MCP Server endpoint.

The workflow connects the chat trigger to the AI Agent, the OpenAI model to the agent's language-model input, Simple Memory to the agent's memory input, and the MCP Client to the agent's tool input.

The AI Agent determines whether the request can be answered directly or whether an MCP tool should be used.

Why MCP Is Used

Without MCP, an AI Agent can become tightly coupled to many individual tools.

With MCP:

AI Agent
   |
   v
MCP Client
   |
   v
MCP Server
   |
   +-- Gmail
   +-- Google Sheets
   +-- Google Docs
   +-- Google Search
   +-- Amazon Search
   +-- Calculator
   +-- Google Calendar

This provides a cleaner separation between:

AI reasoning

Tool exposure

External service integrations

It also makes it easier to add or remove tools from the MCP Server without redesigning the entire AI Agent workflow.

Troubleshooting

1. MCP Client cannot connect

Check:

MCP Server workflow is active.

MCP endpoint is correct.

The n8n domain is reachable.

HTTPS and certificates are working.

The MCP Server path matches MyMCPServers.

2. Tool is not available to the AI Agent

Check the MCP Client's selected tool list.

The AI Agent workflow explicitly selects the MCP tools it can use. Make sure the required tool is included in the MCP Client configuration.

3. Gmail operation fails

Check:

Gmail OAuth2 credential

Required Google account permissions

Recipient address

Subject

Message

OAuth authorization status

4. Google Sheets operation fails

Check:

Google Sheets OAuth2 credential

Document ID

Sheet name

Required Google permissions

Spreadsheet accessibility

5. Google Docs operation fails

Check:

Google Docs OAuth2 credential

Target document

Document permissions

Configured document URL for the Update tool

6. Google or Amazon search fails

Check:

SerpApi credential

SerpApi account/quota

Search query

Amazon domain configuration

The Amazon tool is configured for:

amazon.in

7. Calendar event creation fails

Check:

Google Calendar OAuth2 credential

Selected calendar

Calendar permissions

Event information supplied by the AI Agent

Security Recommendations

For production deployment:

Never commit credentials to Git.

Use n8n credential management.

Use HTTPS for the MCP endpoint.

Restrict access to the MCP endpoint where appropriate.

Use least-privilege OAuth permissions.

Review which tools are exposed through MCP.

Avoid exposing destructive or sensitive tools unnecessarily.

Rotate API credentials periodically.

Monitor n8n executions and MCP requests.

Review AI-generated tool parameters before enabling high-impact automation.

Conclusion

This project provides a practical example of an MCP-enabled AI Agent architecture using n8n.

The MCP Server acts as a centralized tool layer for Gmail, Google Sheets, Google Docs, Google Search, Amazon Search, Calculator, and Google Calendar. The AI Agent communicates with this tool layer through the MCP Client and uses the OpenAI chat model and Simple Memory to process conversational requests.

The architecture can be extended by adding additional n8n tools to the MCP Server and then selectively exposing them to the AI Agent through the MCP Client.
